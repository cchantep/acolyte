# Play demo

Acolyte Play demo for the interactive JDBC tour.

Online demo: [https://acolyte-play-demo.onrender.com](https://acolyte-play-demo.onrender.com)

Legacy tour: [http://tour.acolyte.eu.org](http://tour.acolyte.eu.org)

## Requirements

- **SBT 1.9.9**
- **Play 3.0.12**
- **Scala 2.13.16**
- **Java 17** (local Docker / Render runtime)

## Local development

```bash
sbt compile
sbt test
sbt run
```

Open [http://localhost:9000](http://localhost:9000).

## Docker

Build and run the production image locally (host port **8010**, container `PORT=8000`):

```bash
docker build -t acolyte-play-demo .
docker run --rm -p 8010:8000 -e PORT=8000 -e APPLICATION_SECRET="$(openssl rand -base64 48)" acolyte-play-demo
```

Health check:

```bash
curl -fsS http://localhost:8010/healthz
```

Expected response: `ok`

## Deploy on Render

This app is packaged with a multi-stage **Dockerfile** at the repository root and a Render [Blueprint](https://render.com/docs/infrastructure-as-code) in `render.yaml`.

### Blueprint defaults (`render.yaml`)

| Setting | Value |
| --- | --- |
| Service type | Web service |
| Runtime | `docker` |
| Name | `acolyte-play-demo` |
| Branch | `play-demo` |
| Dockerfile | `./Dockerfile` |
| Region | `frankfurt` |
| Plan | `free` |
| Health check path | `/healthz` |
| Auto-deploy | enabled on pushes to `play-demo` |
| `APPLICATION_SECRET` | Generated by Render on first Blueprint create (`generateValue: true`) |
| `PORT` | `10000` (Render default; container binds `0.0.0.0:$PORT`) |

> Free web services spin down after **15 minutes** without inbound traffic and take about a minute to wake on the next request.

### Create the service from the Blueprint

1. Push this branch (including `Dockerfile` and `render.yaml`) to GitHub `cchantep/acolyte` branch **`play-demo`**.
2. In the [Render Dashboard](https://dashboard.render.com), choose **New → Blueprint**.
3. Connect the `cchantep/acolyte` repository and select branch **`play-demo`**.
4. Confirm Blueprint path `render.yaml` and deploy.

Render provisions the web service, generates `APPLICATION_SECRET`, builds the Docker image, and runs health checks against `/healthz`.

### Manual Web Service settings (without Blueprint)

1. **New → Web Service** from GitHub `cchantep/acolyte`, branch `play-demo`.
2. Language / runtime: **Docker**, Dockerfile path `./Dockerfile`.
3. Region: **Frankfurt**.
4. Plan: **Free**.
5. Health check path: `/healthz`.
6. Environment:
   - `APPLICATION_SECRET` — generate with `openssl rand -base64 48` (or let Render generate a value).
   - `PORT` — optional; defaults to `10000` on Render.

### Environment variables

| Name | Required | Notes |
| --- | --- | --- |
| `APPLICATION_SECRET` | **Yes** | Play production secret. The Blueprint uses `generateValue: true` so Render creates it. Do not commit secrets. |
| `PORT` | No | Render injects `PORT` (default `10000`). The image binds `0.0.0.0:$PORT` and falls back to `8000` locally. |

### Runtime notes

- The container starts Play with `-Dhttp.address=0.0.0.0 -Dhttp.port=${PORT:-8000} -Dpidfile.path=/dev/null`.
- CSRF and AllowedHosts filters are disabled for this demo UI (static JS posts without tokens).
- No database is required; Acolyte is in-process.

### Verify after deploy

```bash
curl -fsS "https://<your-service>.onrender.com/healthz"
curl -fsS -o /dev/null -w "%{http_code}\n" "https://<your-service>.onrender.com/"
curl -fsS -o /dev/null -w "%{http_code}\n" "https://<your-service>.onrender.com/setup.html"
```

Expected: `ok` for `/healthz`, HTTP `200` for `/` and `/setup.html`.
